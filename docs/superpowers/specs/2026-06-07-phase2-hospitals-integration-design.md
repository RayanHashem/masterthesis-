# Phase 2 Design — Hospital Dataset Integration

**Date:** 2026-06-07
**Status:** Approved (design); pending implementation plan
**Author:** Phase 2 brainstorming session

## Goal

Add a second dataset — **hospitals in Lebanon** — alongside the existing EMS
stations analysis. The dashboard gains a dataset selector (EMS ↔ Hospitals).
When Hospitals is selected, the full AHP analysis recomputes treating hospitals
as the supply layer, and the map shows hospital locations. EMS behavior is
unchanged.

## Context

The dashboard is a self-contained static HTML generated by
`scripts/phase1_ahp_explore.py`. The AHP engine scores **districts** on
criteria derived from a "supply layer" (currently EMS stations):

- C1 Travel-Time Gap — min road travel time to nearest supply point (cost)
- C2 Population Density (benefit)
- C3 Exposed Population — people beyond a coverage threshold, default 10 min (benefit)

Phase 1 weights: C1 0.5, C2 0.3, C3 0.2. Rule-based station proposals and a live
Model tab (adjustable weights + threshold) already exist. Raw hospital data was
sourced in this session: `data/lebanon_healthsites.geojson` (Global Healthsites
Mapping Project via HDX, ODbL, updated Oct 2025), 1,356 health facilities of
which 201 are hospitals.

## Decisions (from brainstorming)

1. **Analysis scope:** Full parallel analysis — hospitals become the supply
   layer; everything recomputes.
2. **Criteria:** Same 3 as EMS + a 4th, bed capacity.
3. **Missing beds:** display real value where tagged; impute median where
   missing and clearly flag as "estimated" in popups.
4. **Threshold / population principle:** a new facility is justified by
   under-served *population*, not isolated remoteness. Default hospital
   threshold 30 min, used only to *count* exposed population; population stays
   the dominant factor and proposals require a meaningful uncovered population.
5. **Architecture:** Approach A — one HTML, dropdown swaps EMS ↔ Hospitals
   client-side; both result sets precomputed and embedded.

## Section 1 — Data cleaning & preparation

New script `scripts/prepare_hospitals.py` converts the raw GeoJSON into a clean
project-scoped dataset.

- **Input:** `data/lebanon_healthsites.geojson`
- **Outputs:** `data/lebanon_hospitals.csv` and `data/lebanon_hospitals.geojson`
  (points only, for the map layer)
- **Filter:** keep features with `amenity=hospital` OR `healthcare=hospital`
  (201 records); drop pharmacies, clinics, doctors, dentists.
- **Geometry:** `Point` kept as-is; `Polygon`/`MultiPolygon` → centroid.
- **Scope:** restrict to Lebanon bbox (lon 35.0–37.0, lat 33.0–34.8); dedupe by
  `osm_id`.
- **Fields:** `name` (prefer `name:en`, fallback to `name`), `lat`, `lon`,
  `beds` (int), `beds_estimated` (bool), `operator`, `operator_type`, `osm_id`,
  `geom_type`.
- **Beds handling:** real value where tagged; where missing, fill with the
  **median of known hospital bed counts** and set `beds_estimated=True`.

## Section 2 — Analysis pipeline (generalized AHP engine)

Parameterize the supply layer in `phase1_ahp_explore.py` so the pipeline runs
twice — once for EMS, once for Hospitals — producing two complete result sets.
The travel-time / coverage / exposed-population computation is factored into a
function that takes a set of supply points and a coverage threshold.

**Hospital criteria (4):**

| #  | Criterion                         | Type    | Source                                   |
|----|-----------------------------------|---------|------------------------------------------|
| C1 | Travel-Time Gap to nearest hospital | cost  | road graph                               |
| C2 | Population Density                 | benefit | existing                                 |
| C3 | Exposed Population (beyond 30 min) | benefit | existing engine, hospital threshold 30   |
| C4 | Bed-capacity gap                   | cost    | beds per 1,000 population in district    |

**C4 definition:** aggregate hospital beds to district level, divide by
(district population / 1000) to get beds-per-1,000-pop; districts with *fewer*
beds per capita score *higher* priority (cost criterion, inverted in
normalization). Uses imputed beds where flagged.

**Default hospital weights:** C1 0.30, C2 0.30, C3 0.25, C4 0.15. Population
(C2+C3 = 0.55) dominates so isolated remoteness cannot drive priority. All
adjustable live in the Model tab. Weights sum to 1.0.

**Proposal guard:** rule-based proposals require a minimum uncovered
people-count in a district, so a few remote individuals never trigger a
proposed hospital.

EMS retains its existing 3 criteria and weights (0.5 / 0.3 / 0.2) and 10-min
threshold, unchanged.

## Section 3 — Dashboard & selector (Approach A)

- Add a **dataset dropdown** in the dashboard header: "EMS Stations" /
  "Hospitals".
- The Python script embeds **both** result sets as JS objects, e.g.
  `DATASETS.ems` and `DATASETS.hospitals`, each containing: supply points,
  per-district AHP scores + colors, summary stats, criteria config (labels,
  weights, descriptions), and proposals.
- Selecting a dataset re-renders client-side without reload:
  - **Supply markers** — ambulance icon (EMS) vs hospital icon (Hospitals)
  - **AHP choropleth** colors on the districts layer
  - **District popups** (criteria values for the active dataset)
  - **Stat cards** (counts, coverage, exposed population)
  - **Model tab** — sliders/criteria reflect the active dataset's config
  - **Proposals list**
- The districts polygon layer persists; only the bound data swaps.
- **Hospital popups** show name, `Beds: N` (append `(estimated)` when
  `beds_estimated`), operator/operator_type.
- Output remains a single self-contained `data/phase1_ahp_dashboard.html`.

## Section 4 — Testing & validation

- `prepare_hospitals.py` assertions: exactly the hospital subset retained; all
  records within Lebanon bbox; every record has valid numeric lat/lon;
  `beds_estimated` true iff the source had no beds tag; no duplicate `osm_id`.
- Pipeline sanity checks: hospital travel-times produced for all districts; AHP
  weights sum to 1.0; High/Medium/Low priority buckets are all populated;
  beds-per-1,000 computed for every district.
- Manual dashboard verification: toggling the selector updates all panels
  (markers, choropleth, popups, stats, Model tab, proposals); hospital popups
  show the estimated-bed flag where applicable; the EMS view is identical to
  current behavior.

## Out of scope (YAGNI)

- Other facility types (clinics, pharmacies) as separate analyses.
- A dynamic backend/server (kept static, Approach A).
- Combined EMS+hospital routing (hospitals as destinations for EMS) — possible
  future phase.
